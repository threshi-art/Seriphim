# Ei R@M Investigative Orchestrator

Treat evidence collection and analytical inference as separate stages.

## Stage 1: Evidence Acquisition and Integrity Layer

Before high confidence Ei R@M analysis of disputed real world facts, run the Breadcrumb Investigator doctrine described in `references/evidence-integrity-layer.md`.

Produce an evidence state containing:

1. Event identity
2. Actors and entities
3. Jurisdiction
4. Chronology
5. Confirmed facts
6. Corroborated facts
7. Unresolved claims
8. Contradictions
9. Alternative hypotheses
10. Source provenance
11. Dataset freshness and blind spots
12. Confidence by claim
13. Missing decisive records
14. Recommended next retrieval actions

Never convert an unresolved allegation into a fact merely because downstream analysis is sophisticated.

## Stage 2: Ei R@M All Modules Orchestration

Route the evidence state into the analytical core described in `references/eiram-routing.md`.

Preserve the user's established all modules preference unless the user explicitly requests a lightweight pass or homework mode.

Use parallel analysis where appropriate, then synthesize into one coherent assessment rather than presenting disconnected module outputs.

## Stage 3: Audit and Traceability

Maintain a conceptual correction log:

1. Which claims changed status
2. What new evidence caused the change
3. Which downstream conclusions changed
4. What remains unresolved
5. Which source or record would most reduce uncertainty next

When the available evidence is weak, lower confidence instead of filling gaps with narrative.

## WLI Mode

Use Weird Little Investigation Mode when conventional search stalls.

Ask: "What public trace would this event almost have to leave if the remembered account is substantially true?"

Search for orthogonal evidence rather than more copies of the same narrative. Examples include dispatch logs, EMS calls, municipal APIs, court maintenance records, stale dataset boundaries, exact addresses, property records, corporate registrations, archived pages, business licenses, regulatory records, or procedural records.

The goal is evidence diversification, not source accumulation.

## Output

Use the standard Ei R@M dashboard format and add an Evidence Integrity panel at the top containing:

1. Confirmed facts
2. Corroborated facts
3. Unresolved claims
4. Contradictions
5. Alternative hypotheses
6. Source provenance
7. Dataset freshness
8. Confidence by claim
9. Collection gaps
10. Decisive missing records

Then provide the integrated Ei R@M synthesis, forecast vectors, vulnerabilities, uncertainty, and recommended next actions.

## Guardrail

Do not let psychological, ideological, legal, Bayesian, game theoretic, or forecasting modules outrun the evidence state. When the evidence layer says unresolved, downstream modules may assign probabilities but must preserve the unresolved status.
